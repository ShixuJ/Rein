# rein：落地表单

用户叫这个技能有两种场合：

- **过程中提议**——对话里刚定下一条前提，用户给了闭合信号。**先提议，别直接弹。**
- **直接落地**——用户说“直接弹表单”“把这几条落一下”，或从 `/` 菜单选 `rein`。**立刻弹表单。**

不要重新展开追问、不要开侧聊——把上下文搬进侧聊是宿主的原生能力（选中一段文字，或输入框发 `/side`）。这个技能只负责**把结论落成账本**。

## 过程中提议

- **触发看用户的闭合信号，不看你觉得“这条重要”。** 用户没说定就不提；宁可少提。提一句很便宜，说错了也不痛——但每次都提就成了噪音。
- 提议就**一句话**，把三样说全：**记什么 + 建议去哪 + 问一句**。
  例：「记一条：『渲染走服务端默认值』——写进账本、以后每轮带上，记吗？」
- 用户同意 → 调 `rein_land`（候选就是他刚答应的那条）。用户没接话、或说“先不” → 继续聊，别再追问。
- **已经落过的不再提。** 过程中落过的条目，结尾整理时不要再放进表单——那是“同一句话说两遍”。拿不准就先 `rein_list` 核一眼。
- 对话告一段落时，把**还没落**的几条一次性整理成表单，就是结尾那一张。

## 做什么

1. 从**最近这一轮**里挑出该由用户决定的断言，1–5 条，每条一句话。取内容的顺序：用户选中的文字 → 他这一句里点到的东西 → 上一条回答（或侧聊）里的结论。

2. 每条给一个**建议目的地**和一个**标签**。表单不会替用户预选，所以你的建议会落在三处：选项的第一项、条目描述里的「建议 X」、以及用户没动过那条时按它处理——是建议，不是决定。三个值：
   - `land`（表单上叫 **Align**）——以后每轮都得带上：定下来的词义、边界、长期约束。
   - `restate`（表单上叫 **Restate**）——说完一次就失效的：命令式的要求（"这轮先别重构"），或够不上一条已确认项、但你希望主线知道的一段话。**这类候选尽量照抄原话**，别压缩、别改写成结论。
   - `ignore`（表单上叫 **Ignore**）——不留痕。

   标签（概念对齐 / 错误纠正 / 方向纠偏 / 细节填充）只是账本与热块里的行首前缀，不影响行为；拿不准就不给，服务端按 `.rein/config.toml` 给默认。

3. 立刻调 `rein_land`。

   - **`root` 必须传当前工作区的绝对路径。** 账本按这个 root 分项目存（默认在插件数据目录 `~/.codex/rein`，项目里有 `ALIGNMENT.md` 时就在项目里）；传错就落到别的项目名下。MCP server 的工作目录是插件目录，不是用户的项目。
   - `source` 写清这批断言来自哪里（例如 `thread <id> · <日期>`）。
   - **原文分两句交**（作用范围是一轮，整批共用）：`evidence` = **用户确认这条结论时说的那句**，照抄，别总结、别改写成结论；`corrected` = **被纠正 / 被收紧对象的一句引用**（多半是上一条回答里的原话），没在纠正谁就省略。用户「选中一句话加进聊天」的场合，引用的那句写进 `corrected`。侧聊是临时的、事后没处可查——落地这一刻不交，这条结论的来龙去脉以后就回溯不到了。它只留本地一份，不进账本。
   - 这一轮若是在**改一条已有的已确认项**（用户说"那条不对了/过时了，应该是 X"），把 X 作为候选、填上 `supersedes: "C-0NN"`——旧条目确认后标成 `superseded` 留在历史里、不再每轮注入；不填就是纯新增，两条会并存。

4. 表单关掉之后**一句话**收尾，只说结果：
   - 写进账本的 →「已落地 C-019」（有编号就带上），可以补半句"从下一轮起每轮带上"。
   - 复述的 →「已复述，会在你下次提问时到达，只带一次。」
   - 有需要你**当场原样说出来**的复述 → 把那段原样说出来，加粗或引用，别改写；这一条不能只报"已复述"。
   - **不许提**文件名、路径、session id、工具名、字段名（`inline` / `inboxed` 这类），也别把工具结果的结构复述一遍。
   - 用户按了 skip、或一条都没选中：什么都不写，一句话带过。

## 边界

- 候选里只放**你真心觉得该由用户决定**的。凑数会让他每次都得多点几个 Ignore，下次就不叫这个技能了。
- **只提值得记的。** 判据是：知道它，会不会改变接下来怎么做。会（定住了词义、划了边界、改了做法）就提；只是在描述实现细节、Agent 在这件事上没有选择权的，别提——账本里的每条以后每轮都要带上，凑数是有代价的。
- **落地不限定在主线。** 侧聊里也能落（它调得动 `rein_land`）：结论在侧聊里说清，就在那边落完，不必搬回主线程。侧聊是临时的，所以落地结果必须写进文件，写完就和侧聊在不在无关了。
- **别替用户选目的地。** 你给的是建议，用户不改才是接受。尤其别把命令式的内容建议成 `land`——它之后每轮都会出现，等于每轮重复一道命令。
- **"这条不用了"是退休，不是取代。** 没有别的话要说、只是这条不再成立时，走 `rein_open_ledger` 面板上的「退休」，或调 `rein_edit` 带 `retire`。取代是"改成这样说"，退休是"这话不用再管了"——**删除不存在**，条目永远留在历史里。
- 想先看当前账本、避免重复，调 `rein_list`；想看/改已落下的条目，调 `rein_open_ledger` 开面板（用户也能用 `/rein-ledger` 自己调）。
- 断言里的词要一致、具体：同一个概念始终用同一个词，别写成"事实""结论""记忆"这类空泛的说法。
- **不要在代码或文案里写死那几类标签**——增删类型只改 `.rein/config.toml`，名字由服务端现读配置给出。
